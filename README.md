# 红薯 Agent Studio

面向小红书企业 Agent 基建平台的纯静态前端评审 Demo。三个业务 Agent（社区穿搭灵感、生态守护、电商售后答疑）共用六步流程：创建、配置、调试、评估、发布、监控。所有回答、指标和业务记录均为浏览器内演示数据，不连接真实模型或业务系统。

## 页面结构

项目没有后端服务或构建依赖。网站入口是根目录的 `index.html`，页面样式、浏览器逻辑和 Logo 分别位于 `styles.css`、`src/` 和 `assets/`。

## 发布

将仓库根目录作为静态网站目录发布，入口文件设为 `index.html`，构建命令留空，输出目录设为根目录。页面可以托管在 GitHub Pages 或其他静态网站托管服务。

## 本地预览

在项目根目录启动任意静态文件服务器，然后访问 `http://127.0.0.1:4173/`。macOS 可运行：

```sh
python3 -m http.server 4173
```

该命令仅用于本地预览静态文件，不属于网站运行服务。

## 推荐体验路径

1. **平台能力地图（先看这里）：**左侧「平台能力地图」呈现六层通用骨架、三业务 × 同一套骨架的对比矩阵，以及完整模块清单与 MVP 一期／二期边界和划分理由。带「Demo 已走通」标记的模块可在本原型中点击体验。
2. **B 生态守护 · 质量门槛：**首次评估因严重样本漏判被阻断；在配置启用规则后重评，完成模拟负责人审批再发布。发布后可「暂停建议 · 转人工」，修复后「恢复 Agent 接管」。
3. **A 穿搭灵感 · 灰度与回退：**评估通过后发布到 10% 灰度，在监控页查看灰度决策读数（曝光、采纳率差值、95% 置信区间、护栏指标、放量建议）；放量至 50%、100%（全量后对照组关闭），或回退——回退后该版本评估失效，必须重新评估才能再次发布。
4. **C 售后答疑 · 知识迭代：**在调试体验两轮问答与缺知识转人工；导入 K-02 后重新调试、评估、发布，监控页可展开调用追溯查看版本、指令、知识版本、评估编号与成本。
5. **新建 Agent：**从模板创建，自建 Agent 按所选模板走同一套规则，可在「创建」页删除。

页面状态保存在当前浏览器，刷新后保留。左侧「重置演示」可删除新建 Agent 和所有演示进度（需二次确认）。

## 前端设计

界面使用统一的语义颜色与组件规范，管理页支持搜索，灰度支持滑块或精确输入，图表可展开数据表。规范见 `design-system/agent-studio/MASTER.md`，本轮实际验证与限制见 `docs/ui-redesign-verification.md`。
