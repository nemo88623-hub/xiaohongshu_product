# Agent Studio 可点击评审 Demo

## 目标

让评审者在一个本地网页中体验创建、配置、调试、评估、发布、监控与迭代的完整流程。三个示例 Agent 保留；也可从 A/B/C 模板创建新 Agent。所有数据均为演示数据；页面不调用真实模型、社区内容或政策系统。

## 主要用户与路径

- 平台产品评审者：从工作台新建 Agent 或进入示例，沿六步生命周期查看可操作步骤；管理页显示全部 Agent。
- A 穿搭灵感：修改提示词，运行样例，评估，通过后发布到 10% 灰度，调整流量或回退。
- B 生态守护：初次评估因未启用演示红线规则而失败；启用后重评，审批后发布。最终内容判定保留人工复核。
- C 售后答疑：初次运行缺少具体换码知识；更新演示知识，重新调试和评估，发布新版本。回答必须显示引用，否则转人工。

## 交互与边界

- 使用一套页面结构：工作台、管理列表、模板选择、创建表单、创建信息、配置、调试、评估、发布、监控。
- 新建 Agent 带 `templateType`，调试和评估按模板类型运行；初始仅有草稿，没有生产版本。
- 版本发布保存配置快照和带时间的操作记录；编辑指令、策略、规则或知识会使既有评估失效。
- A 的速度和场景相关性策略会改变模拟回答、离线评分与延迟；评估页显示样本输入、预期、实际和规则依据。
- 未通过评估不可发布；B 还需人工审批。
- A 可回退旧版；B/C 的演示处置为暂停并转人工，避免回到过期政策或知识。
- 所有演示状态保存在当前浏览器，提供重置按钮。
- 界面清楚标注“演示数据”和“模拟回答”。

## 验收

新建 B 和三个原有场景均能从工作台或管理页点击完成；刷新保留状态；重置恢复三个初始示例。监控结果随发布、放量与回退状态变化，始终标注模拟。

## 评审轮增补（对应笔试两道题）

- **平台能力地图**（新页面）：六层通用骨架及其作用、三业务 × 同一套骨架对比矩阵、完整模块清单并标注 MVP 一期／二期与划分理由；Demo 中已走通的模块带标记。
- **灰度决策读数**：曝光量、采纳率差值、95% 置信区间、显著性、护栏指标（p95 预算）与放量／回退建议，由比例检验实时计算，随流量变化。
- **调用追溯**：可展开查看命中版本、当时指令、知识或规则版本、对应评估编号、耗时、tokens 与成本。
- **平台托管能力**（只读）：模型网关、鉴权配额、限流降级、日志追溯、成本核算，说明业务方零搭建的部分。
- **批量跑批**：B 按样本集整批试跑并给出漏判数，与 A 的实时、C 的多轮形成形态差异。
- **评估前后对比与评估历史**：每次评估留痕，可对比上一次的通过样本数。

## 评审轮修正的状态机问题

- 人工兜底新增「恢复 Agent 接管」，不再是单向死路。
- 回退会使该版本评估失效并留下警示，必须重新评估才能再次发布。
- 流量 100% 进入「全量运行」终态，关闭对照组，不再宣称“灰度 100%”。
- 评估失效后不再把过期的评估编号当作发布证据。
- 卡片状态改为由真实字段推导，不再使用装饰性状态；重置与删除均需二次确认。
